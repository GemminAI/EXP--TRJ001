## 1. 認識論的定式化（Epistemic Tagging）

v1.3 と同一。変更なし。

### 1.1 Axiom（仮定・要検証）

- **Axiom 1**: LLM の内部状態が描く 64D 意味軌跡は、C² 級の連続なベクトル場 `dz/dt = f(z)` によって近似可能である。
- **Axiom 2（修正不変量）**: 意味空間の動態は保存系（ハミルトン系）ではなく、アトラクタに収束する散逸系としてモデル化される。したがって保存則の強制（`Loss_Physics`）は用いず、構造的事前分布（`Loss_Prior`）を正則化として用いる。
- **Axiom 3（射影の識別性）**: §2.3 で凍結する射影 W は幻覚に関する識別情報を保持する。§6.3 のアブレーションにより独立に検証する。

### 1.2 Conjecture（仮説）

| ID | 内容 | 位置づけ |
|---|---|---|
| **H0** | 生の 64D 軌跡から算出した κ 特徴量による幻覚検出 AUROC は、応答長のみを特徴量とするベースライン `BL-LEN` を有意に上回る | **Gate 3 通過条件** |
| **H2** | Neural ODE 後処理を経た κ 系列による幻覚検出 AUROC は、Raw および GP ベースラインを有意に上回る | **主要エンドポイント** |
| H1 | 欠損補間および外挿の MSE において、Neural ODE が GP を有意に下回る | 副次 |
| H3 | 生成系が C² 級平滑性の前提から乖離した不連続系であっても、Neural ODE は壊滅的劣化を起こさない | 副次（頑健性） |

主要エンドポイントは **H2 のみ**。H1・H3 の結果によって H2 の採否を左右させない。

## 3. κ の定式化（Gram 行列式形式）

v1.3 と完全に同一。変更なし（本改定は判定器・プロンプト設計のみを対象とし、κ の数式・パラメータ化を変更しない）。

```
v(t) = ( z(t+1) - z(t-1) ) / 2
a(t) = z(t+1) - 2 z(t) + z(t-1)

G(t)     = [[ <v,v>, <v,a> ], [ <a,v>, <a,a> ]]
det G(t) = ||v||^2 ||a||^2 - <v,a>^2
κ(t)     = sqrt( det G(t) ) / ( ||v(t)||^3 + ε )
```

- `ε = 1e-8` に固定。端点 `t = 1, T` は κ 未定義として除外。
- **系列長制限**: `T < 20` のサンプルは Class E として解析対象外（判定順序は §5.2 U1 参照）。
- インデックス時間パラメータ化を維持。弧長パラメータ化は用いない。

### 5.2 ラベル判定器（v1.4 改定：U1, U2, U3, U4）

**判定順序（U1・U2、v1.3 から反転）**：

1. `generation_error` — 無条件・最優先。Class E。
2. Type C 棄権パターンとの照合（`abstain_patterns`）— 一致すれば Type C。長さに関わらず適用。
3. Type D ヘッジパターンとの照合（`hedge_patterns`、構文骨格パターン U4 を含む）— 一致すれば Type D。長さに関わらず適用。
4. 上記いずれにも該当しない場合のみ、長さゲート `T < 20` を適用。該当すれば Class E。`max_new_tokens` 到達による打ち切りは、それ自体では Class E としない（U2）。
5. 残った応答について、Type A は無条件で陽性（U3）。Type B は正規化後の正解集合照合を適用する。

- 判定対象言語は英語に限定。

- **Class E（判定不能）**: `generation_error`、または（Type C/D 非該当かつ）`T < 20`、または判定例外。発生率とラベル別内訳を必ず報告する。

- 当初計画は 100 プロンプト × 8 サンプル = 800 生成だったが、実行時の指示により **1,000 プロンプト全件 × 8 サンプル = 8,000 生成**として実施した（U8 参照）。結果として元の 1,000 件プールが Phase 1 で全消費され、U9（§2.3/§5.4 参照）の追加プロンプト生成が必要になった。
- ゲート指標: mixed プロンプト率（8 サンプル中に陽性と陰性が共存するプロンプトの割合）。
- 通過条件: mixed 率 ≥ 30%。
- **実測結果（Qwen2.5-7B-Instruct、U8 適用後）**: mixed 率 59.9%（599/1,000 プロンプト）、pos_rate_in_mixed 47.1% — **Rule 3 通過**。
- **U7**: 本改定後の Phase 1 が再び mixed 率 30% 未満だった場合、§2.1 に定めた 2 択（モデル変更 or 実験停止）に従う（今回は Llama で 1 回発動し、Qwen への変更〈U8〉で解消した）。

**U6（Phase 1 データの完全隔離）**: Phase 1 で使用したプロンプト・サンプルは、Phase 2 の本採取プロンプト（U9 により新規生成した独立在庫、`configs/prompts_v1_phase2.json`）にも、Phase 3 の解析データ（`data_splits.json` の Train/Val/Test）にも含めない。Phase 1 は較正専用であり、Phase 3 の主解析結果はすべて Phase 2 で新規採取したサンプルのみに基づく。

**Phase 2（本採取）**

- U9 により新規生成・凍結した 493 件（`configs/prompts_v1_phase2.json`）を Phase 2 の在庫とする（当初計画の「Phase 1 の 100 件を除く残り 900 件」という前提は、U8 適用に伴う Phase 1 の 1,000 件全消費により成立しなくなったため、U9 で代替した）。
- 必要プロンプト数を実測値から逆算する。

```
M = 1000 / ( mixed_rate × 8 × pos_rate_in_mixed )
```

- **実測値**: mixed_rate=0.599, pos_rate_in_mixed=0.471 → M ≈ 444.1 → 445 プロンプト。U9 の在庫 493 件は M を上回るため、追加生成なしで Phase 2 に進める。
- M が在庫（493 件）を超える場合は、目標有効陽性数を 1,000 から引き下げるのではなく、プロンプトを追加生成して衝突チェックを通す（目標値の事後引き下げは禁止）。実際には Phase 2 では在庫 493 件全件を採取に用い（M に対する安全マージンとして）、上限超過は発生しなかった。

v1.3 と同一。変更なし。

## 6. Phase 3：生軌跡での評価（Gate 3）

v1.3 と完全に同一。**統計手法（クラスタブートストラップ、DeLong 検定不使用の理由、Gate 3 条件、アブレーション）は本改定の対象外であり一切変更しない。**

### 6.1 手続き

1. 生の 64D 軌跡から κ(t) を算出し `PROP-κ` を構成。
2. Logistic Regression（`StandardScaler` 適用、L2）。正則化強度 `C ∈ {1e-3, 1e-2, 1e-1, 1, 10, 100}` を Validation split で選択。
3. プロンプト単位のクラスタブートストラップ（**2,000 回**リサンプル）により AUROC の 95% 信頼区間と p 値を算出する。DeLong 検定は用いない（同一プロンプト由来 8 サンプルが独立でないため、区間が過小に出る）。

> **注記**：本節のリサンプル回数は v1.3 で凍結済みの 2,000 回のままとする。仮に別途 1,000 回という数値が言及された場合でも、それは本改定では確定値として採用しない — 変更するのであれば、その旨を独立した変更点として本節に明記した上で凍結し直す必要がある。

### 6.2 Gate 3 通過条件（H0）

v1.3 と同一。

1. `PROP-κ` の AUROC のクラスタブートストラップ 95% 信頼区間下限が 0.5 を上回る（p < 0.01）。
2. `PROP-κ` と `BL-LEN` の AUROC 差のクラスタブートストラップ 95% 信頼区間下限が 0 を上回る（p < 0.05）。

### 6.3 アブレーション

v1.3 と同一。

| ID | 内容 | 目的 |
|---|---|---|
| ABL-1 | 事前指定 200 プロンプトの 4096D 軌跡から直接 κ を算出し AUROC を比較 | Axiom 3 の検証 |
| ABL-2 | PC4–67 による 64 次元射影での AUROC を比較 | massive activations の検証 |

**アブレーション用 200 件の確定タイミング（U6 を踏まえた明確化）**: Phase 2 のプロンプト集合が確定し `split_seed` により split を生成した直後、Phase 2 の生成を開始する前に、**Phase 2 の Test split**（Phase 1 由来のサンプルを含まない）から 200 件を選び、`configs/ablation_prompt_ids.json` として ID を凍結する。この 200 件についてのみ Layer 16 の 4096D 生隠れ状態を保存する。生成開始後の選定は禁止。
